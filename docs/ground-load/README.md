# 航空写真の読み込み量（対策の前後）

`tests/e2e/ground-load.spec.ts` で測った、本編の場面ごとの航空写真（PLATEAU-Ortho）の枚数と転送量（MB）。
「うち表示」は、場面が落ち着いた時点で表示に使われているタイル（残りは四分木の途中の段や、カメラの移動中に読んだだけのもの）。
同じタイルの取り直し（解放後の再取得。PLATEAU-Ortho は `cache-control: max-age=3600` なのでブラウザのキャッシュから返る）は数えていない。
ヘッドレス Chromium（SwiftShader）、deviceScaleFactor 1。スマートフォン幅は `screen` も 390×844 にして、`plateauMemoryBudget()` が小さい端末と判定する状態で測った。
対策後の値は、レビューでの修正（取得に失敗した範囲は祖先の画像を表示、移動中も表示の選び方は変えない、撮影範囲の端では段を飛ばさない）を入れた後のもの。

## 見た目

場面1・2・5・6 の落ち着いた時点の画面（`before-*.jpg`・`after-*.jpg`）。目で見て違いは分からない。
場面6 のカメラの移動中と停止後（`motion-6-settled.jpg`・`motion-6-moving.jpg`・`motion-6-stopped.jpg`）: 移動中も停止時と同じタイル（42枚）を表示し、山の裾と地面の位置関係は変わらない。

## 撮影範囲の端のアルファ（晴海ふ頭 35.6475, 139.7700 付近）

PLATEAU-Ortho のアルファは 2 値ではない。ズーム10〜18 の各タイルで、0 と 255 のほかに 1〜254 の中間値の画素が 1〜6% ある（撮影範囲の縁がなめらかに透明になる）。
そのため、途中の段を飛ばすのは、祖先の画像の区画とその周りの区画のすべての画素がアルファ 255 のときに限る。
