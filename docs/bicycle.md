# ママチャリの3Dモデルと大量描画

確認ページ: `demos/bicycles.html`（エントリ `src/demos/bicycles.ts`）。
URL パラメータは `count`（既定 6000）・`view`・`seed`・`buried`・`lod`・`far=1`（全体を原点から西へ 60km に置く）・
`reveal=0.5`（駐輪の列と山積みの先頭の半分だけを表示）・`bench`。

## モジュール

| ファイル | 内容 |
| --- | --- |
| `src/scene/bicycle/geometry.ts` | 形状の生成（3段階の詳細度）、寸法表、部品色、フレーム色パレット |
| `src/scene/bicycle/field.ts` | 大量の自転車のインスタンス描画（まとまりの登録と表示台数、区画ごとの基準点、セル単位の詳細度切り替え） |
| `src/scene/bicycle/layouts.ts` | 確認用の配置（駐輪の列・山積み・1台）と再現可能な乱数 |

座標: 原点は接地面の中央、進行方向 +X、上 +Y、右手側 +Z、1単位=1m。

## 詳細度

| 詳細度 | 三角形数 | 上限 | 内容 |
| --- | --- | --- | --- |
| 近景 (0) | 1,394 | 1,500 | タイヤ・リム（スポーク省略）、U字フレーム、チェーンケース、ワイヤーの前かご、泥よけ、荷台、両立スタンド、サドル、スイープバックのハンドル、ライト、反射板 |
| 中景 (1) | 268 | 300 | タイヤ（リムと一体）、フレーム、平板のチェーンケース、箱のかご・サドル・荷台、泥よけ |
| 遠景 (2) | 38 | 40 | 六角形の輪の車輪、フレームの帯、ハンドルの板、かごの側面 |

どの詳細度も寸法表 `BIKE_DIMENSIONS` から作るので、輪郭（車輪の位置と大きさ、かご、ハンドル）が一致する。

色は頂点カラー。頂点属性 `frameMask=1` の部分（フレーム・フォーク・チェーンケース）にだけインスタンスごとのフレーム色を掛ける。タイヤは黒、かご・泥よけ・荷台は銀。

## 使い方（`BicycleField`）

```ts
const field = new BicycleField();
scene.add(field.object);

// まとまり（駅ごと・山ごと）を登録する。登録した順が出現の順位になる。
// 位置は origin からの相対値で渡す（原点から遠い駅でも float32 の精度が落ちない）。
const akiba = field.addGroup({ ...akihabaraBikes, origin: { x: 1200, y: -0.1, z: -2300 } });
const pile = field.addGroup(pileBikes, { reveal: 0 }); // 最初は 0 台表示
// ……全まとまりを登録してから update を呼ぶ（構築は最初の update でまとめて行う）

// スクロールに合わせて表示する台数を変える（バッファは作り直さない）
field.setRevealCount(Math.round(462 * t), akiba);
field.setRevealCount(Math.round(187_262 * t), pile);
field.setRevealCount(n); // まとまりを省略すると全まとまりに同じ n

// 毎フレーム、描画の前に
field.update(camera, viewportHeightCssPx);
```

- `BicycleInstances.positions` は `Float32Array | Float64Array`。`origin`（倍精度）を指定すると、位置は `origin + positions[i]` になる。
  原点から遠い場所のデータは、近くの基準点を `origin` にするか Float64Array で渡す（Float32Array の絶対座標は 60km で約 4mm 単位に丸まる）。
- `setInstances(data)` は `clear()` と `addGroup(data)` の組み合わせ（互換用）。`removeGroup(id)` もある。
- まとまりの登録・削除は全体の構築し直し（常駐バッファの再転送）になる。本編では最初に全部登録し、以後は `setRevealCount` だけで変える。
- 登録した配列は、次の構築で読み直すので書き換えない。
- `forceLod` は登録の前後どちらで設定してもよい（容量は必要なだけ確保し直す）。

### stats

| 項目 | 内容 |
| --- | --- |
| `total` / `revealed` | 登録台数 / 表示する台数（`setRevealCount` を反映） |
| `visible` / `perLod` / `triangles` | 表示する台数のうち視錐台内のセルにある台数と、その詳細度ごとの内訳・三角形数 |
| `uploadBytes` / `frameUploadBytes` | GPU へ転送したバイト数の累計 / 直近の `update` の分（インスタンスのバッファ・セル状態・表示台数のテクスチャ） |
| `rebuilds` | 近景・中景の層を作り直した回数 |
| `overflow` | 容量を超えて描けなかった台数（通常 0） |
| `drawCalls` | 自転車の描画呼び出し数 |

### 降ってくる動き

```ts
// 表示に加わる自転車が、最終の位置の 60m 上から落ちてくる。落下中は 2,000 台ぶん先まで空中にある。
const g = field.addGroup(data, { reveal: 0, fall: { height: 60, window: 2000 } });
field.setRevealCount(n, g); // 増やすと降り、減らすと（逆スクロール）上から消える
field.reducedMotion = matchMedia('(prefers-reduced-motion: reduce)').matches; // 落下を省く
```

- まとまりごとに表示台数 T と、それを追いかける落下の先頭 A（小数）を持つ。順位 i の落下の進み具合は p = (A − i) / W。
  p ≤ 0 はまだ現れず、0 < p < 1 は空中、p ≥ 1 は着地済み。A は `update` のたびに時間で T + W へ近づく
  （時定数 0.45 秒、最低でも `settleSeconds`（既定 0.8 秒）で残りを降ろし切る）。表示台数が止まっても空中に残らない。
- T を減らすと A を T + W まで下げる（空中に残さない）。一気に増やしても、A は少しずつ進むので落下中は W 台を超えない。
- 位置と向きは頂点シェーダーで決める（物理演算は使わない）。落下の前半 80% で 高さ × (1 − s²) から加速しながら落ち、
  ハッシュで決めた軸のまわりに回る。回転角は (1 − s)² に比例して着地の瞬間に 0（最終の向き）になり、残り 20% で小さく弾む。
- `setRevealCount(n, g, { lead: 0 })` と `pauseFalls = true` で「スクロールしている途中」の静止画を作れる（確認用）。
- 転送はまとまりごとのパラメータ（RGBA float × 2 テクセル = 32 バイト）だけ。着地が終われば 0。
- 視錐台の判定には、落下の高さぶん上へ広げた境界球を使う（詳細度の距離は最終の位置で決める）。

### 山の表面（`setPileSurface`）

成長の段階ごとの山の厚さを DataArrayTexture（半精度、線形補間）で渡し、`setPileSurfaceStage(先頭, 遅れ)` で
現在の段階を uniform で指定する（転送なし）。`addGroup(data, { pile })` と `data.pile`（中心の地表からの高さなど）を使う。

- `mode: 'bury'`（全台を詰めた山）: 現在の表面から深い自転車を描かない。`data.pile.hideAfter`（表示台数がこれを超えると埋もれる）
  でセル単位にも判定し、埋もれる時期の近い自転車を同じセル（16 段階）にまとめるので、全台が埋もれたセルは頂点処理ごと省く。
- `mode: 'lattice'`（表層だけの山）: 自転車を最終の位置から鉛直に spacing 刻みで下げた段のうち、
  現在の表面の下で最も高い段に置く。表面が spacing 上がるたびに一段上へ降り直す（上空から落ちる）。落下の進み具合は
  「遅れ」の表面がその段に追いつく割合で決める。
- どちらも現在の表面からの深さで暗くする（`deepShade`、既定 0.45）。

## 描画の仕組み

- **区画と基準点**: セルを区画（既定 4km 四方）に分け、区画ごとに基準点（区画内の自転車の範囲の中心）を `Object3D.position` に置く。
  インスタンスの位置は基準点からの相対値で GPU に渡す。`modelViewMatrix` は CPU の倍精度で計算されるので、
  原点から 60km の位置でもカメラの移動で自転車が震えない（1mm 移動あたりの画面上の変動: 修正前 約1.5px → 0.0001px、遠景 0.02px。
  `tests/unit/bicycleFieldPrecision.test.ts` が頂点シェーダーの計算を `Math.fround` で再現して確かめる）。
- **遠景の層**: 区画の全インスタンスを固定の並び（まとまり → Morton 順のセル）で GPU に常駐させる。
  セルごとの表示・非表示はセル状態テクスチャ（1セル1バイト）と、区画ごと最大4つの描画範囲で表す。
  描画範囲は同じ常駐バッファを先頭をずらした属性で参照するので、範囲が変わっても転送は発生しない。
- **近景・中景の層**: 割り当てが変わったときだけ、カメラ近くの基準点からの相対位置で作り直す（転送はこの層の台数ぶん）。
- **表示する台数**: インスタンスごとに順位（まとまり内の登録順）とまとまりの番号を持たせ、まとまりごとの表示台数をテクスチャで渡す。
  頂点シェーダーが「順位 ≥ 表示台数」の自転車を画面外へ送る。`setRevealCount` の転送は、まとまりごとに4バイトのテクスチャだけ。
- **視錐台の判定**: セルの境界球の半径に、形状の頂点から求めた半径（`bicycleBoundingRadius()`、全詳細度の最遠頂点 ×1.05 + 0.05m）を足す。
- **フレーム色**: sRGB の8ビットのまま渡し、シェーダーで線形に変換する（暗い色の階調を保つ）。

## 詳細度を切り替える距離

自転車の全長 1.8m が画面上で何ピクセルに見えるかで決める。

- 焦点距離（ピクセル）`f = 画面の高さ(px) / (2 tan(fov/2))`
- 切り替え距離 `d = 1.8 × f / 閾値(px)`
- 既定の閾値は 近景 90px 以上、中景 22px 以上、それ未満は遠景。
  - 例: 高さ 720px・fov 50° なら f ≈ 772px。近景は約 15m まで、中景は約 63m まで。
- セル（既定 6m 立方）ごとに、カメラからセル境界球までの距離で判定する。視錐台の外のセルは描かない。
- 閾値の前後に余裕幅（既定 ±15%、`lodHysteresis`）を設ける。細かくするのは切り替え距離×0.85 を下回ったとき、粗くするのは×1.15 を上回ったとき。
- 近景 2,500 台・中景 20,000 台を上限とし、超えた分はカメラから遠いセルから一段粗くする。
- 山の内部（表面から 1m より深い）の自転車は `lodFloor` で遠景用に固定する（`buried=hidden` で描画から外す）。

## 山の場面（`src/scene/pileScene/`）

確認ページ: `demos/pile-scene.html`（エントリ `src/demos/pile-scene.ts`）。
`?site=marunouchi|shinjuku`・`?t=0〜1`（1 未満は「スクロールの途中」で止めた状態）・`?view=wide|close|street`・`?play=1`・`?reduced=1`。

```ts
import { createPileScene } from './scene/pileScene/pileScene';

const pile = await createPileScene({
  grid: 'marunouchi', lat: 35.6814, lon: 139.766, count: 187_262, mode: 'full',
  onProgress: (p) => console.log(p.phase, p.fraction), // 計算は Web Worker
});
scene.add(pile.object);
pile.setProgress(t);                 // スクロールの進み具合 0〜1
const n = pile.representedCount();   // 本文の数え上げ（'surface' は t × 全台）
// 毎フレーム、描画の前に
pile.update(camera, viewportHeightCssPx);
```

| ファイル | 内容 |
| --- | --- |
| `compute.ts` | 計算の本体（開けた地表に寄せる → 成長の段階 → `fillHeap` → 描画用のデータ）。Node でも動く |
| `pile.worker.ts` / `computeInWorker.ts` | Web Worker で計算し、TypedArray を転送で受け取る。格子は地表の高さ（`height.bin`）だけ読む |
| `pileScene.ts` | `BicycleField`（落下・山の表面）と暗い面をまとめた場面の部品 |

- 成長の段階: 体積で 24 等分した段階に、最初の区間（体積の 1/24 まで）を 8 分割した段階を足す（計 32 段階）。
  等分だけだと最初の区間が「低く広い山」に補間されるため。
- 'full'（1年ぶん）: 全台を成長の順（中心が覆われる順）に並べ、進み具合 t までに覆われる台数を表示する。
  現在の表面から 1.6m より深く埋もれた自転車は描かない（`hideAfter`、セル単位でも省く）。
- 'surface'（15年ぶん）: 最終の表面から法線方向 0.8m の表層だけを置き、成長の途中は表面に合わせて段を下げて置く（降り直し）。
  - 段ごとに表層を置き直す方式は段の切り替えで山の表面が飛び、段ごとの表層を重ねる方式は台数が段数倍
    （32 段で約 18 倍、300 万台超）になる。降り直しは最終の表層の台数のまま、どの進み具合でも表面から 0.8m（法線方向）の層が埋まり、
    表面が上がるにつれて山の全体に自転車が降り続けて見える。
- 暗い面: 山の表面から 'full' 0.9m・'surface' 0.6m 内側。着地済みの段階（落下の遅れ）に合わせて育つ。
- 陰影: 自転車が表面にいる段階の表面の向きと光（`createPlateauStage` の太陽）から明るさを決め、現在の表面からの深さで暗くする。
